# Source and rebuilding BeatSprig 1.0.1

`build-source.json`, generated for each candidate, identifies the exact public application commit and binds `source-release.json`. Use that commit, not a moving branch. This source-delivery manifest currently describes **prepared, unpublished archives**; private qualification does not claim public source delivery or Store release. Before public binary distribution the publisher must make the listed source archives available, independently verify their public bytes, and bind that verification to the final package. No archive URL in this preparation is a claim that an upload already exists.

The public application repository is [hashfunction/beatquay](https://github.com/hashfunction/beatquay). Preserve all original application source, build scripts, headers, UI/resource files, notices and modifications from the recorded commit. The two compiled submodules must be materialized at exactly `src/3rdparty/hiir/hiir` and `src/3rdparty/ringbuffer`, using the commits and archive hashes in `source-release.json`. The remaining excluded instrument submodules are not claimed as components of this minimal binary. If building a complete upstream configuration instead, obtain the additional submodules it uses and observe their own licenses.

The manifest lists 17 immutable source archives: eleven vcpkg dependency source downloads; the full vcpkg `9e593bb18ea69cc5095e012465dcd675a822ed0d` source and recipes; Qt 6.11.2 qtbase, qtsvg and qttools raw-Git source; and hiir/ringbuffer. Archive SHA256, SHA512 and byte counts are explicit. The vcpkg source tar retains all port patches/helpers; copy its dependency source downloads into its `downloads` directory using their recorded filenames. Do not substitute the current upstream branch or a same-named unverified archive. Qt source contains the original bundled third-party code and licenses. QtTools is a build tool; its unexpanded Assistant qlitehtml link is recorded and is not a source claim for a shipped Assistant binary.

To verify a downloaded archive directory, run from the application source root:

```sh
python distribution/native_source.py verify-archives --archives PATH_TO_DOWNLOADED_SOURCE_ARCHIVES
```

This checks all 17 archives against both digests and their exact lengths, refuses symlink/reparse inputs, and leaves them unmodified. The full Qt source archives use `source/` as their top directory. Extract each into a separate module directory; the other archives retain their respective upstream top-level directories. Review member paths and reject links/traversal before extraction. Keep the original archives and hash receipt with the build.

The recorded native build uses Windows x64, MSVC 2022, CMake/Ninja, and Qt 6.11.2 `msvc2022_64`. Install the desktop C++ toolchain and Windows SDK through their supported installers and terms. Bootstrap the pinned vcpkg checkout using `bootstrap-vcpkg.bat -disableMetrics`. Set `CMAKE_TOOLCHAIN_FILE` to that checkout's `scripts/buildsystems/vcpkg.cmake`, both triplets to `x64-windows`, and `CMAKE_PREFIX_PATH` to the chosen Qt prefix. The exact original configure flags and compiler/tool versions are retained in the build evidence. `distribution/qualify-candidate.ps1` contains the complete ordered native configure/build/test/install/render commands; it additionally performs disposable CI qualification and must only be invoked in that environment.

For a modified local desktop build, use its native CMake commands directly with a fresh build and install directory. The minimal configuration is `RelWithDebInfo`, `TARGET_UARCH=official`, `WANT_QT6=ON`, `USE_WERROR=ON`, `FORCE_VERSION=internal`, and `LMMS_MINIMAL=ON`. Disable CARLA, LV2, SUIL, JACK, WEAKJACK, SDL, STK, GIG, SF2, VST, VST_32, VST_64, CALF, CAPS, CMT, SWH, TAP and SID as in the retained command. Build with `cmake --build BUILD`, test with `ctest --test-dir BUILD/tests --output-on-failure`, and install with `cmake --install BUILD --prefix OWN_INSTALL_DIR`. The three approved instrument DLLs link to the executable under its `beatsprig.exe` name. Keep those instruments, the Qt plugins and their dependent DLLs alongside the installed files. Run `beatsprig.exe` directly from your own install directory.

To build a modified Qt, follow the preserved Qt module build scripts and [Qt's Windows source-build instructions](https://doc.qt.io/qt-6/windows-building.html). This is a path to build and modify the corresponding sources, not a guarantee of byte-identical compiler output.
